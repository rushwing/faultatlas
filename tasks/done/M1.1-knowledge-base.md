# M1.1 — Knowledge Base (Ingest Pipeline)

## Status
in_progress

## What we're building

The document upload and processing pipeline: HTTP upload → text extraction → chunking → OpenAI embedding → MongoDB storage → Redis status tracking.

This is Pipeline 1 of 4. It builds the knowledge base that all subsequent retrieval and diagnosis pipelines depend on.

## Files involved

**New / to implement:**
- `services/api/app/routers/ingest.py` — `POST /documents`, `GET /documents/{id}/status`
- `services/ingestion/app/processors/extractor.py` — PDF + plain text extraction
- `services/ingestion/app/processors/chunker.py` — RecursiveCharacterTextSplitter
- `services/ingestion/app/processors/embedder.py` — OpenAI batch embedding
- `services/ingestion/app/storage/mongo.py` — save_chunks(), update_document_status()
- `services/ingestion/app/consumers/document_upload.py` — orchestrates the full pipeline

**Already exists (read, don't modify):**
- `shared/faultatlas/mongo/client.py` — Collections constants
- `shared/faultatlas/redis/client.py` — RedisKeys patterns
- `shared/faultatlas/models/document.py` — DocumentStatus enum

## Constraints / must not break

- Idempotency: same file uploaded twice should return 409, not create duplicate chunks (Redis idempotency key on doc_hash)
- In Phase 1, ingestion is **synchronous** — `POST /documents` blocks until chunking + embedding complete. No Kafka.
- Embeddings stored inline on chunk documents (`chunks.embedding` field) — not a separate collection
